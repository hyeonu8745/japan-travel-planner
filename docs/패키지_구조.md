# TabiMate 백엔드 구조 (패키지 안내)

코드를 처음 볼 때 읽는 문서. 패키지(폴더)마다 무슨 일을 하는지 적었다. 클래스·메서드 설명은 코드 주석(Javadoc)에 있다.

## 전체

TabiMate 백엔드: AI 와 대화하며 일본 여행 일정을 자동으로 만들어 주는 서비스 (Spring Boot).

### 한 번의 여행이 흘러가는 순서
1. 회원가입·로그인 (`user`) → 접근 토큰(1시간) + 갱신 토큰 쿠키(7일)
2. 여행 조건 입력 (`trip`): 날짜·인원·예산·속도·관심사·숙소·공항
3. 취향 대화 (`chat`): AI 가 음식·분위기·이동 제약을 묻고 조건으로 정리
4. 일정 생성 (`itinerary`): 서버가 지역 배정 → 관광지 후보 → 방문 순서 → 점심·저녁 → 시각을 계산하고, AI 는 날짜별 설명 글만 쓴다 (장소·시간은 서버가 정한다)
5. 일정 수정: 식당·관광지 교체, 항목 삭제·순서·추가, 비 오는 날 대안, 채팅 수정, 되돌리기. 고칠 때마다 새 버전으로 저장한다
6. 부가 기능: 식비·교통비 요약, 날씨(`weather`), 환율(`exchange`), 장소 상세(Google), 여행 포스터(`poster`)

### 패키지
- `user` 회원·로그인·토큰 / `trip` 여행 조건·권역·도시 / `chat` 취향 대화·채팅 수정
- `itinerary` 일정 계산·저장·수정 (핵심) / `attraction` 관광지 / `restaurant` 식당(타베로그 데이터)
- `ai` OpenAI 호출 / `global` 보안·예외·Google API·공통 유틸 / `exchange` 환율 / `weather` 날씨 / `poster` 포스터

### 공통 원칙
- 계산은 서버, AI 는 말을 명령으로 바꾸거나 글을 쓰기만 한다. AI 결과는 서버가 다시 검증한다
- AI·외부 API 호출은 트랜잭션 밖에서 (수십 초 동안 DB 연결을 붙잡지 않는다)
- Google Places 내용은 약관상 place ID 말고 저장하지 않는다 (볼 때마다 받아온다)
- 남의 여행은 404 (존재 여부도 숨김, `trip.service.TripAccess`)
- DB 구조는 Flyway(`resources/db/migration`) 가 관리하고 Hibernate 는 확인(validate)만 한다

## 패키지별

### `ai`

OpenAI 호출 공통 부분. 기능별 프롬프트·응답 형식은 각 기능 패키지(chat.ai, itinerary.narration 등)에 있다.

#### `ai.client`

OpenAI Responses API 호출 (`OpenAiClient`): 모델 선택(기본/고급 `AiModelTier`), 요청 조립, 응답 텍스트 추출, 실패 처리, 토큰 사용량 기록.

#### `ai.config`

OpenAI 설정 (`app.openai.*`: 모델 이름, 시간 제한 등). 키는 .env 에만 둔다.

### `attraction`

관광지: 데이터(19개 도시 OSM·위키데이터 관광지 + 예전 도쿄 Google 관광지 중 유명한 곳), 조합 검색, 상세(사진·소개·영업시간·리뷰), 추천하지 않는 장소 정책.

#### `attraction.controller`

관광지 API: `GET /api/attractions/search`(조합 검색), `/{id}/details`(Google 상세), `/{id}/photo`(사진 주소).

#### `attraction.dto`

관광지 API 의 요청 조건·응답 모양.

#### `attraction.entity`

관광지 엔티티 (`attractions` 테이블). 종류는 Google types(도쿄 예전 데이터) 또는 확장 데이터의 `AttractionKind` — `typesOrKind()` 가 kind 를 같은 Google type 이름표로 바꿔서 체류 시간·종류 섞기·관심사·실내외 판단이 둘 다에 같게 동작한다.

#### `attraction.policy`

추천하지 않는 장소 목록 (역사적으로 민감한 곳, 성인 시설 등). 일정 후보·교체 후보에서 뺀다.

#### `attraction.repository`

관광지 조회: 반경 검색(PostGIS), 조건 조합 검색(동적 SQL), 한국어 이름 저장.

#### `attraction.service`

관광지 검색과 상세. 상세는 Google Places 에서 볼 때마다 받아오고 저장하지 않는다.

### `chat`

취향 대화와 채팅 수정.
일정을 만들기 전(PREFERENCE)에는 AI 가 음식·분위기·이동 제약을 묻고 조건으로 정리하고,
일정을 만든 뒤(EDIT)에는 "3일차 점심 스시로 바꿔줘" 같은 말을 명령으로 바꿔 일정 수정 서비스로 넘긴다.

#### `chat.ai`

취향 대화의 AI 프롬프트와 응답 JSON 형식 (Structured Output).

#### `chat.controller`

대화 API: `POST/GET /api/trips/{tripId}/chat/messages`, `GET /api/trips/{tripId}/preferences`.

#### `chat.dto`

대화 API 의 요청·응답 모양.

#### `chat.edit`

일정을 만든 뒤 채팅으로 고치기. AI 는 말을 명령(`EditCommand`)으로 바꾸기만 하고,
후보 찾기·검증·실제 변경은 기존 수정 서비스가 한다. "이렇게 바꿀까요?" 확인을 기다리는 변경은 `PendingEdit`.

#### `chat.entity`

대화 메시지 엔티티 (`chat_messages`).

#### `chat.repository`

대화 메시지 조회 (최근 대화, 시간당 메시지 수 제한용 개수).

#### `chat.service`

대화 흐름: 여행 상태 확인 → AI 호출(트랜잭션 밖) → 정리된 조건과 메시지 저장. 첫 인사, 대화 끝내기 판단, 답이 질문으로 끝나게 하기.

### `dataimport`

확장 데이터 가져오기 (11-16). `import` 프로필로 실행할 때만 동작하고 끝난다(`gradlew bootRun --args="--spring.profiles.active=import"`).
여행·일정·식당·관광지·편의 시설을 비우고 `data/processed/clean_*.json` 으로 다시 채운 뒤, 11-14 백업 값(식당 Google 매칭·한국어 이름)을 다시 붙이고,
예전 도쿄 관광지는 같은 곳이면 Google 장소 ID 를 옮기고 새 데이터에 없는 유명한 곳(리뷰 1,000개 이상)은 더한다. 한 트랜잭션이라 실패하면 그대로다.
관광지 Google 장소 ID·평점 받기는 `places` 프로필(`gradlew bootRun --args="--spring.profiles.active=places"`): 장소 ID 가 없는 관광지 전부(Text Search Pro), 평점은 꼭 가는 곳·인기도 10 이상만(Enterprise). 한 곳씩 바로 저장하고 호출 상한에서 멈추며, 다시 실행하면 이어서 한다.

### `exchange`

엔화 환율: 한국수출입은행 → Frankfurter → 마지막 저장값 → 고정값 순서로, 하루 한 번 받아 저장한다. 실패해도 일정 생성을 막지 않는다.

### `facility`

편의 시설 (`facilities`, OpenStreetMap): 편의점·ATM·코인로커·환전소·관광 안내소·온천·화장실·엘리베이터 등. 숙소 주변 안내에 쓴다 (8단계).

### `global`

여러 기능이 같이 쓰는 것: 설정, 보안(JWT), 예외 처리, Google API 클라이언트, 공통 DTO·유틸.

#### `global.config`

앱 설정: Spring Security(어떤 주소가 로그인 필요, CORS), 서버 시계(Clock) 빈.

#### `global.dto`

여러 API 가 같이 쓰는 응답 모양 (페이지 응답).

#### `global.exception`

예외와 HTTP 상태: 400 `BadRequestException`(우리 문구만 노출), 401 `UnauthorizedException`,
404 `NotFoundException`, 409 `ConflictException`, 429 `TooManyRequestsException`, 503(AI·외부 API).
`GlobalExceptionHandler` 가 모든 응답을 `{"message": "..."}` 로 맞추고, 내부 오류 문구는 로그에만 남긴다.

#### `global.google`

Google API 클라이언트: Geocoding(숙소 주소 → 좌표), Places(장소 상세·사진·식당 매칭 검색), Routes(이동 시간, 기본은 꺼 둠).

#### `global.security`

로그인 인증: 접근 토큰(JWT) 발급·검증, 요청마다 `Authorization: Bearer` 헤더를 읽어 사용자 id 를 넣는 필터.

#### `global.util`

공통 계산: 위경도 거리(Haversine)·좌표 꺼내기, CSV 한 줄 나누기.

### `itinerary`

일정: 이 서비스의 핵심. 계산 파이프라인(`service.ItineraryPlanner`):
지역 배정(`zone`, `candidate`) → 관광지 후보·점수 → 야경 장소 → 방문 순서(TSP, `planner.RouteOptimizer`)
→ 점심·저녁(`meal`) → 시각(`planner.DayScheduler`) → 카페·공항 시간.
AI 는 날짜별 설명(`narration`)과 한국어 이름(`naming`)만 쓴다. 저장은 버전 단위(`entity.Itinerary`).

#### `itinerary.budget`

일정의 식비·교통비 요약 (저장하지 않고 볼 때마다 계산).

#### `itinerary.candidate`

관광지 후보: 점수(보정 평점 + 관심사 + 대화 취향), 날짜별 지역 고르기, 야경 장소, 같은 가게·같은 종류 정리, 비 피하기(실내) 판단.

#### `itinerary.controller`

일정 API (`/api/trips/{tripId}/itinerary/**`): 생성·조회·완성, 식당·관광지 교체, 항목 삭제·순서·추가, 비 오는 날 대안, 버전 목록·되돌리기, 식비 요약.

#### `itinerary.dictionary`

사전: 한국어 음식 표현 → 타베로그 장르, Google 장소 type → 한국어 이름표 (resources/data/*.csv).

#### `itinerary.dto`

일정 API 의 요청·응답 모양 (응답 JSON 은 필드 추가만 한다).

#### `itinerary.entity`

일정 엔티티: 일정 한 버전(`Itinerary`) → 날(`ItineraryDay`) → 항목(`ItineraryStop`). 고칠 때마다 새 버전을 저장하고 옛 버전은 남긴다.

#### `itinerary.fare`

교통비 추정: 대중교통 구간 거리로 숙소 도시의 운임(거리별·정액·패스), 1일권이 싸면 1일권, 공항 이동. 도시별 운임은 `app.fare.cities`(`FareProperties.forCity`), 공항 ↔ 도시는 `AirportAccess`.

#### `itinerary.meal`

끼니: 예산 상한 계산, 음식 조건(좋아함·피함·알레르기·흡연), 반경·예산을 넓혀 가며 식당 찾기, 정기 휴일, 비슷한 음식 반복 감점.

#### `itinerary.naming`

장소·식당 한국어 이름: 일정에 처음 쓰일 때 AI 로 한 번 만들어 DB 에 저장, 장르 한국어 이름표.

#### `itinerary.narration`

날짜별 설명 글(2~3문장)을 AI 가 쓴다. 이미 정해진 일정을 글로만 풀고, 규칙을 어긴 설명은 서버가 버린다.

#### `itinerary.planner`

하루 일정 계산: 방문 순서(TSP), 끼니 넣기, 시각 계산·시간 안 맞으면 고치기, 하루 가능 시간대, 체류 시간, 카페, 공항 이동.

#### `itinerary.reason`

고른 이유: 항목마다 "왜 이곳인지" 칩과, 일정을 만든 뒤 채팅에 남기는 요약. AI 가 아니라 고를 때 쓴 기준에서만 만든다.

#### `itinerary.repository`

일정 조회 (최신 버전, 버전 목록, 하루 생성 횟수).

#### `itinerary.service`

일정 서비스: 생성(`ItineraryGenerationService`), 식당 교체·되돌리기·조건 재계산(`ItineraryEditService`),
관광지 교체·비 오는 날(`ItineraryAttractionEditService`), 항목 삭제·순서·추가(`ItineraryStopEditService`).
버전 저장 공통 흐름은 `ItineraryVersions`, 하루 복사는 `DayCopies`.

#### `itinerary.travel`

이동 시간: 장소 목록의 이동 시간 표를 자체 계산(도보·대중교통·차)으로 만든다. Google Routes 는 일본 대중교통을 주지 않는다.

#### `itinerary.zone`

지역(동네): 하루 일정의 단위. 19개 도시 66개(`TripZone`, 지역마다 반경), 좌표를 반경 안의 가장 가까운 지역에 배정(`ZoneAssigner`). 일정은 숙소 도시(`Trip.baseCity`, 숙소 좌표로 정함 — `AccommodationLocator`)의 지역만 쓴다.

### `poster`

여행 포스터: 일정으로 이미지 AI 가 일러스트 지도 1장 + 상세 일정표 여러 장을 그린다. 오래 걸려서 202 로 바로 돌려주고 따로 그린다.

### `restaurant`

식당: 타베로그 데이터, 조합 검색, 상세(타베로그 + Google), Google 장소 매칭(폐업 확인), 리뷰 분석.

#### `restaurant.controller`

식당 API: `GET /api/restaurants/nearby`·`search`(검색), `/{id}/details`(상세), `/{id}/photo`.

#### `restaurant.dto`

식당 API 의 요청 조건·응답 모양.

#### `restaurant.entity`

식당 엔티티 (`restaurants`): 타베로그 정보 + 예산 숫자 + Google 매칭 결과(place ID 만) + 한국어 이름. 확장 데이터부터 도시·출처(캐글/타베로그/체인점)·휴일 정보. 체인점은 브랜드 표(`chain_brands`)를 가리킨다. 체인점의 장르·예산은 `genreOrBrand()`·`lunchMax()` 등으로 브랜드 값을 쓴다(`ChainGenres`: 한국어 장르 → 타베로그식 장르).

#### `restaurant.match`

타베로그 식당 ↔ Google 장소 매칭: 일정에 고른 식당만 확인해서 폐업·못 찾음이면 후보에서 뺀다.

#### `restaurant.repository`

식당 조회: 반경 검색(PostGIS), 조건 조합 검색(동적 SQL), 매칭 결과·한국어 이름 저장.

#### `restaurant.review`

식당 Google 리뷰를 AI 가 읽고 차별·불친절·위생·좋은 점 경험을 찾는다 (저장하지 않음, 규칙으로 다시 확인). 같은 규칙으로 문장을 훑어 1차 AI 가 놓친 의심 문장만 다시 묻는다(`ReviewSuspects`, `ReviewRecheckPrompt`). 시험 문장 `src/test/resources/review/review_eval.tsv`(156개): 규칙만 재는 `ReviewRulesEvalTest`, 실제 AI 로 재는 `ReviewInsightLiveEval`(REVIEW_EVAL=1 일 때만).

#### `restaurant.service`

식당 검색과 상세 (상세는 처음 열 때 Google 매칭, Google 정보는 볼 때마다).

#### `restaurant.util`

타베로그 예산 글자("￥3,000～￥3,999")를 숫자 범위로 바꾸기.

### `trip`

여행 조건: 날짜·인원·예산·속도·관심사·숙소·공항, 권역·도시, 취향 대화 정리본, 다시 추천하지 않는 식당. 조건을 고치면 일정을 어떻게 맞출지 판단한다.

#### `trip.controller`

여행 API: `/api/trips`(만들기·목록·조회·수정·삭제), `/api/trips/{id}/excluded-restaurants`.

#### `trip.dto`

여행 API 의 요청·응답 모양.

#### `trip.entity`

여행 엔티티와 값: 여행(`Trip`), 상태, 관심사, 여행 속도, 이동 방식, 공항, 취향 정리본(`TripPreference`).

#### `trip.region`

권역(7) → 도시(19) 구조. 여행은 권역을 고르고 날짜마다 도시를 배정한다 (11월 확장 준비, 지금은 수도권·도쿄).

#### `trip.repository`

여행·취향 정리본 조회.

#### `trip.service`

여행 만들기·조회·수정·삭제, 내 여행 확인(`TripAccess`), 조건 변경 판단(`TripChange`).

### `user`

회원: 가입, 로그인(시도 제한), 갱신 토큰·로그아웃.

#### `user.controller`

인증 API (`/api/auth`): signup, login, refresh, logout.

#### `user.dto`

인증 API 의 요청·응답 모양.

#### `user.entity`

회원 엔티티 (`users`).

#### `user.repository`

회원 조회.

#### `user.security`

로그인 무차별 대입 막기 (같은 이메일 + IP 연속 실패 제한).

#### `user.service`

가입·로그인 (비밀번호 BCrypt, 이메일 정규화, 응답 시간으로 가입 여부를 알 수 없게).

#### `user.token`

갱신 토큰: HttpOnly 쿠키, DB 에는 해시만, 쓸 때마다 회전, 폐기된 토큰 재사용 감지, 브라우저 5개 제한, 로그아웃.

### `weather`

여행 날짜별 날씨 (Open-Meteo): 가까운 날은 예보, 먼 날은 작년 같은 날 실제 날씨. 저장하지 않는다.
